# GIMS Smart Merge Report

## 1. Objective
A unified application folder `app-merged` containing the smart-merged full-stack source code of GIMS V1 and V2, resolving role incompatibilities and schema divergences while prioritizing V1's advanced features and preserving V2's data scope.

## 2. Approach & Architecture
We utilized an automated copy strategy for non-conflicting files, and targeted a manual resolution process for the ~50 conflicting files across the backend and frontend. 

**Backend Resolution (Laravel)**:
- **Models**: Unified relationships to ensure V1's specific scopes (`teacher`, `student`, `admin`) coexist natively with V2's scopes (`formateur`, `stagiaire`, `directeur`, `secretariat`).
- **Migrations/Database**: 
  - Overhauled `users` and `attendances` schemas. V1 targeted `student_id` & `teacher_id` while V2 targeted `seance_id`. The unified migration safely hosts both foreign keys and nullables to adapt dynamically.
- **Controllers**:
  - `DashboardController`, `AuthController`, and `UserController` were completely rewritten using `match($role)` expressions to correctly load payloads for any of the 8 roles.
- **Security Check**:
  - Maintained complete encapsulation. A `formateur` or `teacher` cannot see unassigned modules or out-of-scope `groupe`s. A `parent` only sees their children's data.

**Frontend Resolution (React/Typescript)**:
- **Component Preservation**: V1 React components provided a highly mature UI (including `AcademicYearsPage`, comprehensive Dashboard, multi-role views). V1 views were selected as the source of truth for all frontend conflicts.
- **Role Unification**: The frontend Types `User` schema natively recognizes the union of all standard roles: `'admin' | 'teacher' | 'student' | 'parent' | 'directeur' | 'secretariat' | 'formateur' | 'stagiaire'`.
- **Axios & Context**: Preserved robust V1 QueryClient caching behavior (`queryClient.clear()` on logout for security cleanup).

## 3. Post-Merge Initialization Guide

To initialize and run the newly minted unified stack, follow these steps:

### Backend
1. `cd app-merged/backend`
2. `composer install`
3. `cp .env.example .env` (Update database credentials in `.env`)
4. `php artisan key:generate`
5. `php artisan migrate:fresh --seed`
6. `php artisan serve`

### Frontend
1. `cd app-merged/frontend`
2. `npm install`
3. `npm run dev`

> **Note**: Default credentials generated by `DatabaseSeeder.php` are explicitly listed in the seeder, generally utilizing `password` securely hashed for local development. Make sure your local testing DB matches the new unified schema migrations before production deploy.
